# B OAuth fixed IPv6 egress

Deployed 2026-10-31 for the 1,073 existing, non-deleted OpenAI OAuth accounts.
Each persisted account ID has a dedicated proxy record and source address:
`2a02:ae02:1a:2c00:937b:: + account ID`. Addresses do not depend on tokens,
model, request, or process lifetime. API-key accounts are outside this scope.

The loopback-only CONNECT adapter listens on `127.0.0.1:26443`. Per-account
proxy credentials select an immutable mapping loaded from a private config.
ChatGPT TLS tunnels use the existing relay at `127.0.0.1:25443`, with its
`S2RLYIP6` version 1 source-address preface. Auth/API OpenAI tunnels bind the
same IPv6 directly using Linux IPV6_FREEBIND. Only these three hosts on port
443 are allowed. TLS remains end-to-end. There is no IPv4 or random-IP fallback.

Existing account proxy support carries the binding through HTTP, WS, token
refresh, usage and privacy requests. Proxy-specific connection caches separate
accounts. Established pre-change connections drain normally; new connections
use the binding. Existing relay services and their other clients are unchanged.

Runtime: `/root/candidates/b-account-ipv6-20261031`, container
`sub2api-b-account-ipv6`, image `sub2api-b:account-ipv6-20261031`.
The parent directory is mode 0700. Do not commit generated configs or secrets.
The supplied scripts are records of this deployment, not a general migration:
`prepare.py` refuses to overwrite its backup; `bind.py` checks original proxy
ownership and writes scheduler events in the same transaction; `rollback.py`
restores original bindings only where this release still owns the proxy.
Leave the adapter running when rolling back so active tunnels can finish.

Validation: unit checks for authentication and target restrictions; 12 fresh TLS
trace connections across three hosts and two accounts all matched assigned IPs;
two recently active accounts returned 200 from authenticated read-only usage;
1,073 distinct account/proxy mappings, zero unbound OAuth accounts, refreshed
scheduler snapshots, 115 observed live IPv6 connections, zero adapter dial errors.

Build on Linux: `CGO_ENABLED=0 GO111MODULE=off go build -o account-ipv6-proxy main.go`.
Tests: `GO111MODULE=off go test main.go main_test.go`.

Automatic allocation was enabled on 2026-10-31 in
`/root/candidates/b-account-ipv6-auto-20261031`, container
`sub2api-b-account-ipv6-auto`, listening on `127.0.0.1:26445`.
The old adapter stays running for established tunnels. All 1,073 legacy proxy
credentials and IPv6 addresses were preserved; the newly discovered account was
backfilled, bringing the verified total to 1,074.

`automatic.sql` installs a policy local to the B database. A BEFORE trigger
assigns a private proxy in the same transaction as account insertion, import,
duplication, conversion or restoration; an AFTER trigger publishes the scheduler
event. It also restores the account's own binding when a client attempts to copy
another account's proxy or clear its binding. Non-OpenAI/OAuth accounts are
excluded. Failed account transactions roll back proxy creation as well.

The adapter authenticates new account IDs using a domain-separated SHA-256
credential containing a 256-bit server secret, generated by PostgreSQL. Only
canonical positive decimal IDs below 2^48 are accepted. Their IPv6 is computed
from the fixed base plus ID. The database and adapter share the secret through
private deployment configuration; it is never included in this repository.
Legacy credentials take precedence. New accounts require no config reload,
periodic job, or adapter restart. Back up the config and policy table together.

`install_auto.py` is a one-time release script. Run after staging and testing the
new adapter; it updates existing proxy ports, enables automatic assignment, and
backfills missing accounts transactionally with bounded lock waits. Validate
`automatic_test.sql` on an isolated schema first. Its production verification
uses inactive synthetic accounts inside an explicitly rolled-back transaction.
Tests cover creation, duplicate isolation, edits, restoration, type conversion,
non-target isolation and scheduler events; TLS trace checks verify that SQL
generated credentials produce the expected source IPv6 without any config edit.

To disable automatic assignment, disable the two `b_oauth_ipv6_*` triggers in a
short transaction. Leave the new adapter running: already assigned new accounts
depend on its automatic credentials. Do not revert all ports to the legacy
adapter, which cannot authenticate those new accounts. Existing tunnels must
drain naturally during any future adapter replacement.
