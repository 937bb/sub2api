## Preserved and Restored Behavior

The release preserves the custom quota expansion and 429 handling, OAuth/PAT WS
selection, IPv6 relay configuration, account-scoped identities, and fingerprint
isolation across HTTP, WS, shadow accounts, and reconnection attempts.

Official merge omissions were restored in group model allowlists, simple-mode
group APIs, multi-turn WS admission, later-turn error handling, model-not-found
failover, final-model instruction selection, and API-key authentication snapshots.
The WS passthrough path again records the original requested reasoning effort
separately from the applied effort, including subsequent turns, and supplies the
canonical model to model-scoped 429 handling.

All 42 existing OpenAI OAuth accounts retained their distinct persisted seeds;
55 API-key accounts have no such seeds. Existing account modes were not changed.
`openai_oauth_ws_default_enabled=true` remains enabled.
`openai_codex_fingerprint_default_full_enabled=false` remains unchanged:
independent account identity is not the same as full session convergence.

## Database Compatibility

Before candidate startup, `deploy/sql/v023-rolling-compat.sql` was applied in a
transaction with a one-second lock timeout. Both `models_list_config` and
`model_allowlist` remain available, with a bidirectional trigger synchronizing
writes from old and new instances. Official migrations 235/236 were then applied
without modifying their checksums; the existing fingerprint migration 237 was
preserved. All 54 group rows match across the two columns. No active group had
an enabled allowlist at deployment time.

Keep the compatibility column and trigger until old instances and rollback
requirements have been retired. Removing either while a legacy instance is
running can break its database queries.

## Live Routing

Host: `84.32.220.70`. The primary `sub2api-b` runs the new image on **6064**.
Both `tob.937ai.chat` and `tob.apihelm.com` retain their existing Nginx routes.
The C application's upstream URLs remain `http://127.0.0.1:6064`; its container,
CPA, CPAMP, and the pre-existing `16068` canary were not restarted or replaced.

The candidate on 36064 was validated before any new-connection routing changed.
Scoped IPv4/IPv6 NAT temporarily redirected new 6064 connections while the old
primary drained. The primary was recreated only after its connections drained;
the candidate continued serving during startup. New-connection NAT was removed
after the new primary passed direct readiness and Docker health checks.

`sub2api-b-v023` (36064) and `sub2api-b-fingerprint` (26064) are retained only
while their existing connections drain. The finalizer counts half-closed
connections as well as established connections, since a half-closed client may
still be receiving a stream. It does not force termination to meet a deadline.
It removes only these two temporary containers after they drain, then disables
the release-specific units. Inspect actual state before any later update:

```bash
docker ps --filter name=sub2api --format '{{.Names}} {{.Image}} {{.Status}}'
systemctl status 937sub2b-v023-finalize.timer
journalctl -u 937sub2b-v023-finalize.service -n 20 --no-pager
```

Ports `6064,16068,26064,36064` are reserved against ephemeral client allocation.

## Known Check Limitations

The separate `-tags=unit` suite still has legacy contract mismatches and image
tests referring to removed symbols; it is not passing. Full golangci-lint was
run on the final code and reports 14 issues: one dependency-boundary warning,
eight unchecked test errors, one test formatting warning, and four unused
declarations. This is not a clean-lint or all-build-tags-green release.

## Evidence and Recovery

Root-only deployment directory:
`/www/wwwroot/sub2api-b/releases/0.2.3.1`.

It contains the original Compose file and checksum, protected group and
fingerprint snapshots, candidate/finalizer scripts, verification logs, image
identity, and a source archive. Do not expose configuration or seed snapshots.
The source archive includes the uncommitted changes used for this build.

For rollback, first stop the finalizer timer and route new connections to a
healthy compatible candidate. Wait for the primary's active and half-closed
connections to drain, then restore the protected Compose backup and recreate
only `sub2api-b`. Validate direct 6064 health and the public routes before
removing temporary routing. Keep the dual-column compatibility schema during
rollback. Never use `docker compose down`, a database restore, or forced stream
termination for this release.
